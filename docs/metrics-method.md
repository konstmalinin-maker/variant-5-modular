# Методика метрик

Измерения выполняются одним Python 3.12/Linux окружением. В таблицах раздельно указаны .py всего (включая тесты/скрипты) и production .py. LOC — физические строки (включая пустые/комментарии), максимальная длина — максимум среди всех .py. Число каталогов приложения — уникальные родительские каталоги production-модулей, корень не считается. Кэши и venv исключены.

Число внутренних импортов — AST-рёбра Import/ImportFrom между production-модулями с точным совпадением имени; динамические зависимости не учитываются. Средняя CC — стандартные блоки radon.complexity.cc_visit только production-кода; полный radon cc . включает ещё тесты/скрипты, поэтому его среднее отличается. Сырые файлы сохранены отдельно.

Coverage — фактический coverage.json; тесты и время — JUnit данного запуска. Сравнение исходных архитектур сделано на одинаковом контракте 45 тестов, итоговые версии имеют дополнительные тесты DI/границ и потому их время не характеризует чистую стоимость архитектуры.

Поиск выполняется одинаковой командой rg -l 'def enroll\(' --glob '*.py' . три раза на текущем дереве. Поиск add_note из примера PDF заменён на enroll по варианту №5. Время включает запуск процесса и зависит от кэша; миллисекундная разница не доказывает преимущество навигации человеком.

Экспорт и замена хранилища реально внесены отдельными коммитами; список изменённых файлов получен git status --porcelain, включая новые __init__.py и конфигурацию. Таймер охватывает автоматизированные изменения файлов до линтера и тестов; результат не выдаётся за скорость программирования человеком. После каждого эксперимента тесты реально запускались.
